# 마이챌린지 운영 모델 v2.0 — 커뮤니티 중심으로

작성 2026-11-23. 홈페이지 v2.0의 기준 문서입니다. `docs/*.docx` 기획서(MC-01~05, 통합 기획서 v2.0)는 v1 운영 방식(12주 라운드, 챌린지 심사, 합의서 서명, 수익 배분과 정산)을 기록한 문서이며, 지금 운영 방식은 이 문서를 따릅니다.

---

## 1. 무엇이 바뀌었나

| | v1 (라운드·배분 중심) | v2 (커뮤니티 중심) |
|---|---|---|
| 출발점 | 리더가 챌린지를 제안 → 운영본부 심사 | 정기모임에서 함께 살펴본 관심사 |
| 단위 | 12주 라운드 안의 솔로·그룹·오피셜 챌린지 | 학습그룹·도전그룹 (기간은 그룹리더가 정함) |
| 누가 여나 | 리더(L4) 이상 + 심사 통과 | 운영진이 승인한 그룹리더 (등급 무관), 언제든 |
| 시작 조건 | 합의서 전원 서명 + 운영본부 승인 | 그룹을 만들면 바로 모집 시작 |
| 참여 관리 | 주간 체크인 제출 | 모임마다 출석 코드, 그룹리더가 정한 출석 규칙 |
| 이탈 처리 | 무단 이탈 시 기여율 50% | 출석 경고 → 퇴출 기준 → 리더 결정(또는 자동), 이의 신청 |
| 돈 | 배분 순서·비율, 정산표, 지급, 운영본부 몫 | 정하지 않음. 실제 수익이 나는 그룹이 생기면 함께 정해 먼저 공개 |
| 최종 목표 | 외부 매출과 정산 | 수익목표 6단계(배움 → 실행 → 첫 반응 → 첫 매출 → 반복 매출 → 성장) |
| 마무리 | 데모데이 → 페이퍼 → 정산 | 성과발표회 → 페이퍼, 완주 배지 |
| 북극성 지표 | 완주하고 매출까지 낸 회원 | 최근 30일 그룹 모임에 나온 회원 |

바꾼 이유는 세 가지입니다.

1. **사람이 먼저 모여야 프로젝트가 생깁니다.** 아직 그룹 프로젝트에서 실제 수익이 나기 전인데 배분 규칙과 서명 절차가 앞에 있으면, 시작하기 전에 지칩니다. 지금은 사람과 그룹이 모이고 움직이는 데 집중합니다.
2. **딱딱한 문서 대신 가벼운 약속과 기록.** 합의서 서명을 빼는 대신, 그룹마다 공개된 목표와 출석 규칙에 동의하고 참여합니다. 약속을 지켰는지는 출석 기록과 도전 기록이 보여 줍니다.
3. **최종 목표는 그대로 성과와 수익.** 배움에서 끝나지 않도록 수익목표 단계를 두고, 매출은 운영진이 증빙으로 확인합니다.

## 2. 운영 흐름

```
정기모임(월 1회 이상, 온·오프라인)
  │  발제: 사업 아이디어 · 시장 분석 · 트렌드 · AI 활용 · 사이드프로젝트 · 그룹 소식
  │  새 그룹 소개, 함께할 사람 찾기
  ▼
그룹리더 신청 → 운영진 승인(5일) → 그룹 만들기(언제든)
  │  학습그룹: 한 분야를 함께 공부·실습·정리
  │  도전그룹: 하나의 프로젝트로 셀 수 있는 목표에 도전
  ▼
그룹 모임(그룹리더가 정한 주기) ── 모임마다 출석 코드 ── 출석 규칙(경고·퇴출)
  │
  ├─ 도전 기록(진행·학습 노트·자료·회고) → 커뮤니티 '그룹 소식' 공유
  ├─ 성과 기록(매출·고객·판매·사용자·콘텐츠·학습 과제) → 목표 진행률
  └─ 매출 증빙 → 운영진 확인 → 첫 매출 배지
  ▼
성과발표회(시즌마다) → 그룹 종료 → 완주 배지 → 프로젝트 페이퍼 → 공개
```

홈페이지와 오프라인 모임은 같은 흐름을 나눠 맡습니다. 정기모임·성과발표회·오프라인 그룹 모임은 현장에서, 기록·출석 집계·성과·공유는 홈페이지에서 합니다. 출석 코드는 현장 화면이나 온라인 대화창 어디서든 같은 방식으로 씁니다.

## 3. 그룹 운영 설계

### 3-1. 그룹리더
- 등급과 관계없이 운영진 승인으로 정합니다. 신청서(종류·주제·계획·경험·시간)와 활동 기록(정기모임·그룹 모임 출석, 도전 기록, 완주)을 함께 봅니다.
- 동시에 이끄는 그룹은 기본 2개, 회원이 동시에 참여하는 그룹은 기본 3개(규칙 설정에서 조정).
- 부리더를 지정해 모임과 출석 관리를 나눕니다.
- 운영진은 그룹리더 자격을 거둘 수 있고, 그룹리더를 교체할 수 있습니다(사유를 그룹원 모두에게 알림).

### 3-2. 그룹 만들기
목표 문장, 목표로 세는 숫자와 수치, 기간, 마일스톤, 모임 주기·장소, 정원(기본 8명, 최대 20명), 참여 방식(승인·바로 참여), 대화방, 출석 규칙. 학습·도전그룹 예시를 눌러 빈칸을 채울 수 있게 해 처음 여는 리더의 부담을 줄였습니다.

### 3-3. 출석 규칙
그룹리더가 그룹마다 정하고, 회원은 참여 신청 때 규칙을 확인했다고 표시합니다. 기본값과 근거는 아래와 같습니다.

| 항목 | 기본값 | 근거·의도 |
|---|---|---|
| 지각 | 시작 10분 뒤 | 국내 대학 수업과 사내 교육에서 흔히 쓰는 기준. 온라인 모임 접속 지연을 감안 |
| 지각 환산 | 3번 = 결석 1번 | 대학 학칙에서 널리 쓰는 방식. 지각을 반복하는 것도 참여 약속으로 봄 |
| 공결 | 사전 사유, 최대 2번 | 사정은 인정하되 무한정 빠지지 않도록 상한. 대학의 공결 상한과 같은 발상 |
| 최소 출석률 | 70%, 3번째 모임부터 | 처음 1~2번은 그룹이 자리 잡는 기간이라 경고에서 뺌 |
| 경고 | 연속 결석 2번, 또는 출석률이 기준 아래로 떨어질 때 | "말없이 사라지는" 패턴을 일찍 알리려는 것. 한 모임에 경고는 한 번 |
| 퇴출 | 경고 2번이면 퇴출 대상, 기본은 리더가 사정을 듣고 결정 | 자동으로 내보내지 않는 것을 기본으로. 리더가 원하면 자동 퇴출을 켬 |
| 이의 | 운영진에게 이의 신청, 운영진은 기록을 보고 리더와 이야기 | 퇴출은 그 그룹에만 해당하고, 다시 받으면 이전 경고는 모두 취소 |

출석 계산은 공결을 분모에서 빼고, 지각 환산분을 결석으로 더해 출석률을 냅니다. 출석은 마감한 모임만 셉니다. 리더가 마감을 잊어도 모임이 끝나고 12시간 뒤 자동으로 마감되어, 출석 집계가 리더의 성실도에 따라 들쭉날쭉하지 않게 했습니다.

### 3-4. 기록과 공유
- 도전 기록: 진행 기록, 학습 노트, 자료 공유, 회고, 공지(리더). 응원과 고정.
- 커뮤니티 게시판: 그룹 소식, 정보·자료, 아이디어, 시장·트렌드·AI, 질문, 후기, 공지.
- 다른 그룹의 도전 기록 전체 열람은 어치버(L3)부터. 공유한 기록은 모든 회원이 봅니다.

## 4. 수익목표

| 단계 | 기준 | 확인 방법 |
|---|---|---|
| 1. 배움 | 함께 공부하고 정리한 결과가 남음 | 학습 과제·정리 노트 기록 |
| 2. 실행 | 만들기 시작함 | 시제품·판매 페이지·첫 콘텐츠 링크 |
| 3. 첫 반응 | 모르는 사람의 반응 | 인터뷰·문의·사전 신청·구독자 수 |
| 4. 첫 매출 | 그룹 밖 고객의 첫 결제 | 증빙 → 운영진 확인 → 첫 매출 배지 |
| 5. 반복 매출 | 다시 팔림 | 재구매·정기 고객, 반복 매출 배지(운영진) |
| 6. 성장 | 그룹 뒤에도 프로젝트가 이어짐 | 페이퍼의 '지금 상태' |

도전그룹은 목표를 숫자로 세우고(매출·유료 고객·판매·사용자·콘텐츠·학습 과제·직접 정한 지표), 성과를 기록할 때마다 진행률이 올라갑니다. 가족·지인·회원 사이의 거래는 매출 확인에서 뺍니다.

### 수익을 나누는 방식
**정하지 않았습니다.** 실제 수익이 나는 그룹이 생기면 그 그룹과 운영진이 함께 방식을 정하고, 적용하기 전에 `/goals/`에 공개합니다. 그 전에는 다음만 지키도록 안내합니다.
1. 돈을 받거나 쓰기 전에 그룹원끼리 방식을 먼저 정하고 그룹 기록으로 남긴다.
2. 잃어도 되는 돈으로만 한다(대출·카드 할부·회원 간 금전 대여 금지).
3. 이견이 생기면 운영진에게 조정을 요청한다.

이용약관 제10조(수익목표와 수익)에 같은 내용을 두었습니다.

## 5. 운영진의 지원

| 지원 | 내용 |
|---|---|
| 그룹리더 지원 | 승인, 워크숍, 운영 가이드(`docs/그룹리더-가이드.md`), 첫 모임 전 목표·출석 규칙 점검 |
| 정기모임과 발제 자리 | 그룹 소개·모집, 다른 그룹 근황, 정보 교류 |
| 세미나·워크숍 | AI 도구, 판매 페이지, 가격, 콘텐츠, 세금 등 실무 |
| 오피스아워 | 막힌 그룹과 함께 보기, 필요한 기술을 가진 회원 연결 |
| 그룹 운영 도구 | 모임 일정, 출석 코드, 출석률·경고 자동 계산, 도전 기록, 목표 진행률, 성과 기록 |
| 성과 확인과 소개 | 매출 확인과 배지, 성과발표회, 프로젝트 페이퍼 |

운영진은 운영 화면에서 모임이 끊긴 그룹, 출석을 받지 않은 모임, 출석률이 낮은 그룹, 퇴출 기준에 닿은 그룹원을 자동으로 확인하고 그룹리더에게 먼저 연락합니다.

## 6. 참고한 사례

- **독서·취향 모임 플랫폼**: 모임마다 운영자(클럽장·호스트)를 두고, 참석 전에 짧은 글(독후감 등)을 내는 것을 참여 조건으로 삼거나, 호스트가 참여 신청을 승인하는 방식. → 그룹리더 승인제, 리더의 참여 신청 승인, 도전 기록.
- **6주 안팎의 빌더 프로그램과 데모데이**: 짧은 기간 동안 각자 만들고 매주 진행을 공유한 뒤 마지막에 발표하는 구조. → 기간을 그룹이 정하는 그룹 모임, 시즌마다 성과발표회.
- **"첫 1달러" 문화(인디 해커 커뮤니티)**: 금액보다 처음으로 모르는 사람이 돈을 낸 순간을 이정표로 삼음. → 수익목표 4단계와 첫 매출 배지.
- **대학 학칙과 동아리 출석 관리 앱**: 지각 기준, 지각 환산, 공결 상한, QR·코드 출석, 역할별 권한, 출석 통계 자동 집계. → 출석 코드, 출석 규칙 기본값, 부리더, 출석표.

## 7. 지표

- 북극성: **최근 30일 그룹 모임에 나온 회원 수**(마감한 모임의 출석·지각).
- 보조: 그룹 모임 출석률, 회원 그룹 참여율, 출석 경고·퇴출, 그룹 완주, 첫 매출 회원, 정기모임 참석률, 발표 수.
- 정의는 `docs/KPI-정의.md`.

## 8. 예전 자료 이전

v1 데이터가 있는 D1에서는 첫 요청 때 마이그레이션이 한 번씩 실행됩니다(`schema_migrations`). 챌린지는 그룹으로 옮겨집니다. 솔로·그룹·오피셜 챌린지는 도전그룹이 되고, 합의 중·정산 중이던 것은 진행 중으로, 제안·심사·반려 단계는 중단으로 바뀝니다. 그룹을 이끌던 회원은 그룹리더 자격을 받고, 마챌데이·데모데이·스터디 일정은 정기모임·성과발표회·워크숍으로, 품앗이 게시글은 정보·자료로 옮겨집니다. 예전 합의서·장부·정산 표는 지우지 않고 남겨 둡니다(화면에서는 쓰지 않음). 예전 주소 `/rules/`, `/guide/profit-sharing/`는 `/goals/`로 301 이동합니다.

## 9. 아직 정하지 않은 것

- 그룹 수익을 나누는 방식 (위 4장)
- 정기 멤버십·참가비 (생기면 금액과 환불 기준을 숫자로 먼저 공지)
- 반복 매출 배지의 확인 기준 (지금은 운영진이 회원 상세에서 직접 부여)
