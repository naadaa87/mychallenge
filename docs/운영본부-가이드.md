# 운영본부 콘솔 사용 안내 (v1.2)

회원 공간에 운영진 계정으로 로그인한 뒤 위쪽 메뉴의 **운영**(휴대폰에서는 아래쪽 **운영** 탭)을 누르면 들어옵니다. 주소는 `/app/#/admin`입니다.

화면은 왼쪽 메뉴와 오른쪽 본문으로 나뉩니다. 휴대폰에서는 왼쪽 메뉴 대신 위쪽의 **☰ 메뉴** 버튼을 누르면 전체 메뉴가 열립니다. 어느 화면에서든 위쪽 검색창에 닉네임, 이름, 이메일, 챌린지 제목을 넣으면 바로 찾아갑니다. Enter를 누르면 첫 결과로 이동합니다.

---

## 1. 권한: 운영진과 운영자

| 할 수 있는 일 | 운영진 | 운영자 |
|---|:---:|:---:|
| 받은 일 처리 (가입, 챌린지 심사, 합의서, 정산, 페이퍼, 승급, 이의·신고) | ✓ | ✓ |
| 회원 등급·배지·상태 조정, 임시 비밀번호 | ✓ | ✓ |
| 단체 알림, 일정·출석, 커뮤니티 관리 | ✓ | ✓ |
| 지급 처리, 운영본부 재원 기록 | ✓ | ✓ |
| 장부·정산·지급·페이퍼·포인트 CSV | ✓ | ✓ |
| 규칙 설정 변경 | – | ✓ |
| 회원·가입 신청·동의 기록 CSV, 전체 백업 | – | ✓ |
| 운영진 지정·해제, 다른 운영진의 정보 변경 | – | ✓ |

- 처음 만든 계정(초기 설정 계정)이 자동으로 운영자가 됩니다. v1.1에서 쓰던 사이트라면 가장 먼저 만든 운영진 계정이 운영자가 됩니다.
- 운영자는 최소 한 명이 있어야 하고, 자기 자신의 운영진 권한은 해제할 수 없습니다.
- 운영진을 늘릴 때는 **사람 → 운영진**에서 가입한 회원의 이메일이나 닉네임을 넣습니다.

## 2. 매일 할 일: 현황과 받은 일

**현황** 첫 줄의 "오늘 처리할 일"이 받은 일 7가지의 합계입니다. 카드마다 처리 기한이 적혀 있고, 기한이 지난 건은 빨간 테두리와 "기한 지남"으로 표시됩니다.

| 받은 일 | 기한 | 이렇게 처리합니다 |
|---|---|---|
| 가입 신청 | 3일 | 지원서를 읽고 승인하면 초대 코드와 보낼 안내문이 뜹니다. **안내문 복사**를 눌러 이메일이나 카톡으로 보내세요. 여러 건은 체크한 뒤 **선택한 신청 승인**으로 한 번에 처리합니다. 반려는 한 건씩 사유를 남깁니다. |
| 챌린지 심사 | 7일 | 심사표 6항목에 점수를 매기면 가중 합계가 바로 계산됩니다. 금지 유형이나 이해충돌에 체크하면 점수와 관계없이 통과하지 않습니다. 의견은 제안자에게 그대로 갑니다. |
| 합의서 승인 | 3일 | 배분이 프리셋 ±10%p 안인지, 소유와 이탈 조건이 분명한지, 특약이 원칙과 충돌하지 않는지 확인하고 승인합니다. 승인하면 챌린지가 시작됩니다. |
| 정산 검수 | 7일 | 정산표를 열어 장부·증빙과 금액을 맞춰 보고 검수합니다. |
| 페이퍼 검토 | 5일 | 수익 보장 표현, 다른 사람의 개인정보, 장부와 어긋난 숫자, 안 된 것을 숨겼는지를 봅니다. |
| 승급 심사 | 7일 | 기록상 조건 충족 여부가 표시됩니다. 보류·반려에는 사유를 꼭 적습니다. |
| 이의·신고 | 7일 | 1차는 당사자끼리, 2차는 운영본부가 조정합니다. 종결할 때 결과를 기록합니다. |

현황 아래쪽에는 다음이 있습니다.

- **핵심 지표**: 완주하고 매출까지 낸 회원(북극성 지표), 최근 7일 접속 회원, 진행 중인 그룹, 이번 주 체크인 제출률, 첫 매출 회원, 공개된 페이퍼. 모두 실제 기록에서 바로 계산합니다.
- **주의가 필요한 곳**: 아래 상황을 자동으로 찾아 보여 줍니다. 누르면 해당 그룹이나 회원 화면으로 갑니다.
  - 10일 넘게 체크인이 없는 그룹
  - 최근 체크인 제출이 절반 미만인 그룹
  - 2주 연속 체크인을 내지 않은 그룹원 (3주면 무단 이탈 기준)
  - 7주차 첫 공개 마감을 넘긴 그룹
  - 예정 기여율과 실제 기여율이 20%p 넘게 차이 나는 그룹원
  - 검수 후 7일이 지났는데 지급하지 않은 정산
- **회원 흐름**: 가입 신청 → 계정 생성 → 오리엔테이션 → 메이커 이상 → 그룹 참여 → 라운드 완주 → 첫 매출. 가장 많이 멈추는 단계부터 손봅니다.
- **최근 8주**: 가입 신청, 새 계정, 체크인 제출, 완료 로그의 주간 추이. 막대에 마우스를 올리면 숫자가 보입니다.

## 3. 사람

**회원**에서는 등급·상태·운영진 여부로 거르고, 최근 접속순이나 포인트순으로 정렬할 수 있습니다. 이름을 누르면 회원 상세가 열립니다.

회원 상세에서 볼 수 있는 것:
- 참여한 챌린지별 체크인 제출 수, 투입 시간, 확인된 완료 기록, 기여율(예정 → 실제)
- 다음 등급까지 남은 조건
- 포인트 내역(항목별)
- 등급·배지 이력. 배지는 여기서 회수할 수 있습니다.
- 기본 정보, 자기 자산 진단, 가입 신청서, 동의 기록, 일정 참석
- **내부 메모**: 운영진만 보는 메모입니다. 통화 내용, 확인한 증빙, 다음에 볼 것을 남겨 두면 다른 운영진도 같은 맥락에서 이어 갈 수 있습니다.

**등급·배지·상태 관리** 버튼으로 등급 조정, 배지 부여(첫 매출 배지는 포인트도 함께), 휴면·제명을 처리합니다. 사유는 회원에게 알림으로 갑니다. **임시 비밀번호**는 비밀번호를 잊은 회원에게 직접 전해 주세요. 창을 닫으면 다시 볼 수 없습니다.

## 4. 챌린지

**그룹 현황**은 진행 중인 챌린지가 멈추지 않았는지 보는 화면입니다.

| 표시 | 뜻 |
|---|---|
| ● 순조 | 최근 2주 체크인 제출률 60% 이상, 6일 안에 움직임 있음 |
| ▲ 주의 | 제출률 60% 미만이거나 6일 넘게 조용함 |
| ■ 위험 | 체크인 기록이 없거나 10일 넘게 조용함 |

위험한 그룹은 그룹장에게 먼저 연락합니다. 그룹을 누르면 주차별 제출률, 그룹원별 기록, 마일스톤, 장부 요약, 처리 이력, 내부 메모가 한 화면에 나옵니다.

**운영본부 조치**(중단·종료·재개, 그룹장 교체)는 사유를 받아 그룹원 모두에게 알림으로 보냅니다. 그룹장 교체는 그룹원들의 동의를 먼저 확인한 뒤에 합니다(MC-03 4.4). 중단한 챌린지도 페이퍼는 냅니다.

**라운드**에서 모집 마감일을 정하고 상태를 **모집**으로 두면 홈페이지 첫 화면과 가입 신청 페이지에 "○기 모집 중 · 마감일 · 시작일" 안내가 자동으로 뜹니다. 마감일이 지나거나 상태를 바꾸면 안내가 사라집니다.

## 5. 돈

**지급 관리**는 검수가 끝난 정산금을 입금하고 기록하는 화면입니다.

1. 정산표 검수가 끝나면 그룹원별 지급 건이 **지급 대기**에 생깁니다.
2. 그룹원 계좌로 이체합니다. 원천징수 대상은 세후 금액(실지급)을 보냅니다. 계좌 정보는 사이트에 저장하지 않으니 각자에게 따로 받아 주세요.
3. 입금한 건을 체크하고 **입금했어요 → 지급 처리**를 누릅니다. 받는 사람에게 알림이 가고, 한 정산의 모든 건이 끝나면 정산 상태가 "지급 완료"로 바뀝니다.

운영본부로 들어오는 몫(운영본부 몫, 정산 대행 수수료, 선지원 회수)도 같은 화면 아래쪽에 있습니다. 이것까지 처리해야 정산이 완료됩니다.

**운영본부 재원**에는 분기별 수입(운영본부 몫 + 수수료)과 쓴 돈이 정리됩니다. 사례집 인쇄, 강사비, 홈페이지 비용, 다음 라운드 선지원 등에 돈을 쓰면 여기에 기록하세요. 최근 4개 분기의 수입과 항목별 쓰임은 공개 사이트의 [수익 배분 규칙](/rules/#hq-report) 페이지에 자동으로 공개됩니다. 기록이 하나도 없으면 "아직 공개할 숫자가 없다"는 문장만 보입니다.

## 6. 소통

- **단체 알림**: 모든 회원, 특정 등급 이상, 라운드 참여자, 특정 챌린지 그룹원, 진행 중인 챌린지의 그룹장, 운영진 중에서 받는 사람을 고릅니다. 받는 사람 수가 바로 계산되니 확인하고 보내세요. "공지 게시판에도 올리기"를 체크하면 커뮤니티 공지에 같은 글이 올라갑니다. 알림은 회원 공간 안에서만 가고, 이메일·문자는 보내지 않습니다.
- **커뮤니티 관리**: 신고된 글을 확인하고 숨기거나 신고를 기각합니다. 숨길 때 적은 이유는 작성자에게 알림으로 갑니다. 댓글도 숨길 수 있습니다. 애매하면 숨기기 전에 작성자에게 먼저 물어보세요.
- **일정·출석**: 일정을 만들면 상세 화면에 출석 코드가 크게 나옵니다. 현장에서 화면에 띄워 두면 됩니다. 코드를 넣지 못한 사람은 신청자 목록에서 직접 **출석 처리**합니다. 포인트는 한 번만 들어갑니다. 일시나 장소를 바꾸면 신청자에게 알림을 보낼 수 있고, **일정 취소**는 사유와 함께 신청자 모두에게 알립니다.

## 7. 설정

- **규칙 설정**: 돈 규칙, 그룹·심사, 승급 조건, 열람 권한, 활동 포인트, 배분 프리셋을 입력 양식으로 바꿉니다. 묶음마다 **이 묶음 저장**을 누르면 바꾸는 이유를 묻고, 이유는 변경 이력에 남습니다. 기본값에서 바꾼 묶음에는 "기본값에서 바꿈" 표시와 **기본값으로** 버튼이 나옵니다. 규칙은 라운드 시작 전에만 바꾸고, 바꾼 내용은 마챌데이에서 공지합니다. 이미 승인된 합의서에는 소급되지 않습니다.
- **감사 로그**: 누가 언제 무엇을 처리했는지 남습니다. 처리한 사람, 행동 종류, 대상으로 거를 수 있고 **더 보기**로 이전 기록을 이어서 봅니다. 감사 로그는 지울 수 없습니다.
- **데이터·백업**: CSV 내려받기, 전체 백업(JSON), 표별 데이터 수, 적용된 구조 변경을 봅니다. 라운드가 끝날 때마다 백업 파일을 한 번씩 받아 안전한 곳에 보관하세요. 비밀번호 해시와 로그인 세션은 백업에 들어가지 않습니다. Cloudflare D1 자체도 30일 시점 복구를 지원합니다.

## 8. 운영 리듬

| 언제 | 할 일 |
|---|---|
| 매일 20분 | 현황 → 받은 일 비우기 |
| 월요일 | 그룹 현황에서 ▲·■ 그룹 확인, 그룹장에게 연락 |
| 매월 | 마챌데이 일정 등록·출석, 규칙 변경 공지, 재원 사용 기록 |
| 라운드 시작 전 | 라운드 만들기(모집 마감일), 규칙 확인, 일정 등록 |
| 라운드 말 | 데모데이 → 페이퍼 검토 → 정산 검수 → 지급 → 승급 심사 → 백업 |

## 기술 메모

- 새 기능에 필요한 표(운영자 권한, 내부 메모, 단체 알림 기록, 재원 사용)는 첫 요청 때 자동으로 만들어집니다. 기존 표에 붙는 열(라운드 모집 마감일, 일정 취소 상태, 댓글 숨김)은 `schema_migrations`에 기록하며 한 번씩만 추가합니다. Cloudflare에서 따로 할 작업은 없습니다.
- API는 `functions/_lib/admin-routes.js`(현황·회원·그룹·지급·재원·알림·커뮤니티·일정·감사·백업)와 `functions/api/[[path]].js`(받은 일 처리)에 나뉘어 있습니다.
- 화면은 `public/app/views/admin/` 폴더에 메뉴 묶음별로 나뉘어 있습니다: `home.js`, `inbox.js`, `people.js`, `groups.js`, `money.js`, `comms.js`, `system.js`, 공통 `shared.js`.
- 점검: `npm test`(API 전체 흐름, v1.2 포함), `node tests/admin-flow.js`(브라우저에서 검색·규칙 변경·알림·메모·권한 확인), `node tests/screenshots.js [--mobile]`(운영 화면 22개 캡처).
