# 마이챌린지 KPI 정의

운영본부 콘솔 **분석 → KPI 지표**(`/app/#/admin/kpi`)에 나오는 숫자가 무엇을 세는지 정리했습니다.
숫자를 보고 판단하기 전에, 그 숫자가 무엇을 세지 않는지도 같이 확인해 주세요.

---

## 1. 어떻게 모으나

### 방문 기록

공개 사이트와 회원 공간의 모든 페이지에 `public/assets/track.js`가 들어 있습니다. 이 스크립트가 세 가지를 서버(`POST /api/t`)로 보냅니다.

| 기록 | 언제 | 담는 것 |
|---|---|---|
| 페이지 보기 (view) | 페이지를 열 때, 회원 공간에서 화면을 옮길 때 | 주소, 제목, 처음 온 브라우저인지, 방문의 첫 페이지라면 들어온 사이트와 UTM |
| 머문 시간 (leave) | 다른 페이지로 갈 때, 탭을 숨기거나 닫을 때 | 화면이 실제로 보인 초 (최대 30분), 페이지를 어디까지 내려 봤는지(%) |
| 클릭 (click) | 링크·버튼·FAQ 질문을 누를 때 | 이동한 곳, 누른 글자(50자), 위치(첫 화면·본문·맺음 띠·머리글·바닥글) |

- **방문자**는 브라우저 저장소에 넣은 무작위 번호(`machal_vid`)로 셉니다. 같은 사람이 휴대폰과 PC로 오면 2명으로 셉니다. 브라우저 저장소를 지우면 새 방문자가 됩니다.
- **방문**은 30분 넘게 아무것도 하지 않으면 끝난 것으로 봅니다(`machal_sid`).
- 로그인한 회원은 회원 번호가 함께 저장되어 회원별 활동에 쓰입니다.
- IP 주소와 브라우저 정보(User-Agent)는 저장하지 않습니다.

### 세지 않는 것

- 운영진 계정으로 로그인한 상태의 방문 (서버와 화면 양쪽에서 걸러 냅니다)
- 운영본부 화면(`/app/#/admin…`)
- 검색 로봇, 미리보기 봇, 헤드리스 브라우저
- 브라우저에서 '추적 안 함(Do Not Track)'이나 Global Privacy Control을 켠 방문자

그래서 실제 방문보다 조금 적게 나옵니다. 네이버 서치어드바이저나 구글 서치 콘솔, 제작자 관리 프로그램(choisijun.com)의 숫자와는 기준이 달라서 맞지 않는 것이 정상입니다.

### 언제부터 모으나

방문 기록은 **2026년 11월 25일**부터 모읍니다. 개인정보처리방침에 이용 통계 항목을 더한 날(11월 18일)로부터 7일 뒤입니다. 처리방침 12항에 "내용을 바꾸면 시행 7일 전에 알린다"고 적어 두었기 때문에, 시행일 전에는 `/api/t`가 기록을 받지 않고 버립니다.

- 운영자는 요약 탭의 **목표·수집 설정**에서 수집 시작일을 바꾸거나 수집을 끌 수 있습니다. 바꾼 내용은 감사 로그에 'KPI 목표·수집 설정'으로 남습니다.
- 앞으로 처리방침의 이용 통계 항목을 다시 바꾸면, 바꾼 내용을 올린 날로부터 7일 뒤로 시작일을 옮기면 됩니다.
- 수집을 끄면 그 기간의 방문·페이지·클릭 숫자만 비고, 회원·모임·커뮤니티 숫자는 그대로 나옵니다.

### 회원·모임·커뮤니티 숫자

가입 신청, 회원, 챌린지, 체크인, 일정, 글·댓글 숫자는 방문 기록이 아니라 데이터베이스에 있는 실제 기록으로 셉니다. 이 숫자들은 KPI 기능을 넣기 전 기록까지 모두 정확합니다.

### 보관 기간

방문 기록은 13개월이 지나면 지웁니다(서버가 몇 시간에 한 번씩 오래된 기록을 정리). 회원이 탈퇴하면 방문 기록과 회원 번호의 연결을 끊습니다. 방문 기록은 전체 백업(JSON)에 넣지 않습니다.

## 2. 기간과 비교

- 기간은 **7일 / 30일 / 90일 / 1년** 중에서 고르고, 오늘(한국 시간)까지 포함합니다.
- **직접 고르기**를 누르면 시작일과 끝일을 정할 수 있습니다. 최대 1년(366일)까지이고, 끝일이 오늘보다 뒤면 오늘까지로 자릅니다. 고른 기간은 주소에 남아서(`?start=2026-12-01&end=2026-12-31`) 그대로 다른 운영진에게 보낼 수 있습니다.
- 비교 대상은 **바로 앞 같은 길이의 기간**입니다. 30일을 보면 그 앞 30일과 비교합니다.
- ▲·▼ 옆 숫자는 개수는 증감률(%), 비율은 차이(%p)입니다. 초록색은 좋아진 쪽, 빨간색은 나빠진 쪽입니다. '한 페이지만 보고 나간 비율'과 '중도 이탈률'은 줄어야 좋아진 것으로 봅니다.
- 방문 기록이 지난 기간 전체를 덮지 못하면(기능을 넣은 지 얼마 안 됐을 때) 방문 지표는 비교하지 않습니다.
- 추이 막대는 31일 이하면 하루, 120일 이하면 주(월요일 시작), 그보다 길면 월 단위로 묶습니다. 맨 오른쪽 진한 막대는 아직 끝나지 않은 오늘(이번 주·이번 달)입니다.

## 3. 요약 탭

다섯 묶음으로 나눴습니다. 위에서 아래로 "사람이 들어오나 → 회원이 되나 → 움직이나 → 모임이 채워지나 → 결과가 나오나" 순서입니다.

| 묶음 | 지표 | 정의 |
|---|---|---|
| 유입 | 방문자 | 기간 안에 페이지를 한 번이라도 본 브라우저 수 |
| | 페이지뷰 | 열어 본 화면 수 (공개 사이트 + 회원 공간) |
| | 방문당 머문 시간 | 머문 시간 합계 ÷ 방문 수. 화면이 보인 시간만 셉니다 |
| | 한 페이지만 보고 나간 비율 | 페이지를 하나만 본 방문 ÷ 전체 방문 |
| 전환 | 가입 신청 | 기간 안에 들어온 가입 신청서 수 |
| | 방문자 → 신청 전환율 | 가입 신청 ÷ 방문자 |
| | 새 회원 | 기간 안에 초대 코드로 계정을 만든 회원 |
| | 오리엔테이션 완료율 | 기간 안에 가입한 회원 중 지금 챌린저(L1) 이상인 비율 |
| 참여 | 활동 회원 | 기간 안에 회원 공간을 방문했거나 체크인·완료 기록·글·댓글·일정 출석·장부 기록이 있는 회원(운영진 제외) |
| | 체크인 제출률 | 기간 안에 열린 체크인마다 그때 그룹원 수를 더한 값 대비 실제 제출 수 |
| | 일정 참석률 | 기간 안에 열린 일정의 신청자(취소 제외) 중 출석한 비율 |
| | 커뮤니티 글·댓글 | 회원이 쓴 글과 댓글 수 (숨긴 글, 운영진 글 제외) |
| 모임 | 새로 개설된 모임 | 기간 안에 제안된 그룹·오피셜 챌린지 (솔로 제외) |
| | 모임 참여 신청 | 그룹원으로 지원한 수 (그룹장 제외, 수락 여부와 무관) |
| | 진행 중인 모임 | 지금 모집·합의·진행·정산 단계인 그룹 |
| | 회원 모임 참여율 | 정회원 중 지금 진행 중인 그룹에 활동 그룹원으로 있는 비율 |
| 성과 | 라운드 완주 | 기간 안에 완주 배지를 받은 회원 |
| | 첫 매출 | 기간 안에 첫 매출 배지를 받은 회원 |
| | 처음 온 방문자 비율 | 방문자 중 이 브라우저로 처음 들어온 비율. 홍보가 새 사람에게 닿는지 봅니다 |
| | 신청서 제출 방문 | 브라우저에서 가입 신청서 제출을 마친 방문 수 |

**정회원**은 상태가 활동 중이고 오리엔테이션을 마친(L1 이상) 회원입니다.

### 이번 달 목표

요약 탭 맨 위 카드입니다. 고른 기간과 상관없이 **이번 달 1일부터 오늘까지**를 셉니다.

- 목표를 정할 수 있는 지표: 방문자, 페이지뷰, 가입 신청, 새 회원, 활동 회원. 운영자가 **목표·수집 설정**에서 정하고, 0이거나 비우면 카드에 나오지 않습니다.
- 막대는 지금까지 숫자 ÷ 목표입니다.
- **월말 예상**은 지금까지 숫자 ÷ 지난 날 수 × 이달 날 수로 단순하게 늘린 값입니다. 월초 며칠은 크게 흔들리니 둘째 주부터 보는 편이 낫습니다. 홍보를 한 번 크게 한 주가 있으면 실제보다 높게 나옵니다.
- 활동 회원은 날마다 더해지는 숫자가 아니어서 월말 예상을 내지 않습니다.
- 이번 달 방문자는 그달에 한 번이라도 온 브라우저 수입니다. 하루 방문자를 더한 값이 아닙니다.

## 4. 방문·유입 탭

- **유입 출처**: 방문의 첫 페이지를 기준으로 들어온 곳을 나눕니다. 네이버 검색·블로그·카페, 구글, 다음, 카카오, 인스타그램, 페이스북, 스레드, X, 유튜브, 링크드인, 브런치, 티스토리, AI 검색·대화(ChatGPT·Perplexity 등)는 이름으로 묶고, 그 밖의 사이트는 도메인 그대로 보여 줍니다. 들어온 사이트 정보가 없으면 '직접 방문'입니다. 카카오톡 인앱 브라우저나 일부 앱은 출처를 넘기지 않아 '직접 방문'으로 잡힐 수 있습니다.
- **신청 전환율**: 그 출처로 시작한 방문 중 신청서 제출까지 간 비율.
- **캠페인(UTM)**: 홍보 링크에 `utm_source`, `utm_medium`, `utm_campaign`을 붙이면 따로 셉니다.
  - 예: `https://mychallenge.kr/apply/?utm_source=instagram&utm_medium=bio&utm_campaign=1기모집`
  - 링크를 어디에 뿌렸는지 구분하고 싶을 때 `utm_source`만 바꿔서 쓰면 됩니다.
- **기기·영역·시간대·요일**: 방문자가 어떤 기기로, 어느 영역(공개 사이트·페이퍼·회원 공간)을, 언제 보는지. 공지나 홍보 글을 올릴 시간을 정할 때 씁니다.

## 5. 콘텐츠 탭

| 항목 | 정의 |
|---|---|
| 가입 신청까지 | 전체 방문 → 가입 신청 버튼을 누른 방문 → 가입 신청 페이지를 본 방문 → 신청서 제출 |
| 가입 신청 버튼을 누른 곳 | `/apply/`로 가는 링크를 누른 페이지와 위치 |
| 많이 본 페이지 | 페이지뷰, 방문자, 평균 머문 시간, 스크롤, 첫 페이지로 들어온 수, 바로 나감(그 페이지로 들어와 그 페이지만 보고 나간 비율), 여기서 떠남(방문의 마지막 페이지였던 비율), 클릭 |
| 스크롤 | 방문마다 그 페이지를 가장 많이 내려 본 위치(%)의 평균. 화면 아래 끝이 문서 전체 높이의 몇 %까지 왔는지로 잽니다. 짧은 페이지는 열자마자 100%가 됩니다 |
| 가장 많이 읽은 가이드 | `/guide/…` 글별 페이지뷰와 평균 머문 시간. 읽는 데 걸리는 시간과 비교하면 끝까지 읽혔는지 짐작할 수 있습니다 |
| 많이 펼친 질문 | FAQ에서 열어 본 질문 |
| 많이 누른 링크·버튼 | 이동한 곳과 누른 글자 기준 |
| 프로젝트 페이퍼 | 공개 페이퍼 페이지 열람 + 회원 공간 전문 열람(`view_logs`) |
| 회원 공간에서 많이 쓴 화면 | 번호를 지워서 화면 종류별로 묶습니다 (`/app/groups/:id/checkin` 등) |

### 페이지 상세

'많이 본 페이지' 표에서 페이지 이름을 누르면 그 페이지만 따로 봅니다(옆의 ↗는 실제 페이지를 새 탭으로 엽니다).

- 위 카드: 페이지뷰·방문자·첫 페이지로 들어온 수, 평균 머문 시간, 스크롤, 여기서 떠남·바로 나감
- 날짜별 페이지뷰 추이
- **이 페이지에서 누른 것**: 링크·버튼 글자와 이동한 곳, 위치. 이 페이지에서 가입 신청서 제출 같은 목표를 마쳤다면 따로 보여 줍니다
- **이 페이지로 바로 들어온 출처**: 이 페이지로 방문을 시작한 경우의 유입 출처
- **바로 앞에 본 페이지 / 다음에 본 페이지**: 같은 방문 안에서 이 페이지 바로 전과 바로 다음에 연 페이지. 누르면 그 페이지의 상세로 넘어갑니다

글을 고칠 때 쓰기 좋습니다. 스크롤이 30%대에서 멈추는 가이드라면 앞부분에서 읽기를 그만두는 것이고, 다음에 본 페이지에 `/apply/`가 거의 없다면 글 끝의 안내가 약한 것입니다.

## 6. 회원 탭

- **DAU / WAU / MAU**: 오늘 / 최근 7일 / 최근 30일 동안 활동한 회원 수. 기간 선택과 무관하게 항상 오늘 기준입니다. 활동의 정의는 요약 탭의 '활동 회원'과 같습니다.
- **고착도**: DAU ÷ MAU. 한 달에 한 번이라도 온 회원 중 오늘도 온 비율입니다. 주간 체크인 중심 모임이라 높게 나오기 어렵고, WAU ÷ MAU를 같이 보는 편이 맞습니다.
- **잠든 회원**: 정회원 중 30일 넘게 접속하지 않은 회원.
- **가입 흐름**: 위 세 줄(신청 → 승인 → 계정 생성)은 기간 안에 들어온 신청서, 아래 세 줄(L1 → L2 이상 → 모임 참여)은 기간 안에 가입한 회원 기준입니다.
- **가입 월별 최근 30일 활동률**: 가입한 달별로, 그 회원들 중 최근 30일에 활동한 비율. 오래된 기수일수록 떨어지는 속도를 봅니다.
- **회원별 활동**: 활동한 날, 본 화면 수, 머문 시간, 체크인, 완료 기록, 글·댓글, 일정 출석(기간 안), 진행 중인 모임 수, 누적 포인트. '조용한 회원 먼저'로 정렬하면 연락이 필요한 회원을 먼저 볼 수 있습니다. CSV로 받을 수 있습니다.

## 7. 모임·참여 탭

| 지표 | 정의 |
|---|---|
| 모임 평균 인원 | 진행 중인 그룹의 활동 그룹원(그룹장 포함) 평균. 설명에 충원율(활동 인원 ÷ 최대 8명)과 최소 4명 이상인 그룹 비율을 함께 보여 줍니다 |
| 지원 수락률 | 그룹원 지원 중 받아들여진(활동·이탈·제외 포함) 비율 |
| 중도 이탈률 | 그룹에 들어온 사람 중 이탈하거나 제외된 비율 |
| 완주율 | 끝난 그룹(종료 + 중단) 중 종료로 끝난 비율 |
| 일정 참석률 | 기간 안에 열린 일정의 신청자 중 출석 비율 |

**모임별 참여 현황** 표에는 그룹마다 지원·수락·활동 인원·충원율·체크인 참여율(제출 수 ÷ 체크인 수 × 활동 인원)·완료 기록·이탈·외부 매출이 나옵니다. 진행 중인 그룹 중 활동 인원이 최소 인원에 못 미치면 '최소 미달'이 붙습니다.

**일정 참석** 표는 마챌데이·세미나·커피챗 같은 일정별 정원, 신청, 출석, 참석률입니다.

## 8. 커뮤니티 탭

- 글·댓글·도움돼요는 회원이 쓴 것만 셉니다(운영진 공지와 숨긴 글 제외).
- **질문 답변율**: 질문 게시판 글 중 작성자가 아닌 회원의 댓글이 하나라도 달린 비율.
- **반응이 많았던 글**: 도움돼요 × 2 + 댓글 수 순서. 읽음은 회원 공간에서 그 글을 연 횟수입니다.

## 9. 보는 순서 제안

| 언제 | 볼 것 |
|---|---|
| 매주 월요일 | 요약 탭 7일: 활동 회원, 체크인 제출률, 진행 중인 모임 / 회원 탭 '조용한 회원 먼저' |
| 홍보 글을 올린 다음 날 | 방문·유입 탭 7일: 유입 출처, 캠페인 / 콘텐츠 탭 가입 신청까지 |
| 매월 마챌데이 전 | 요약 탭 30일 전체, 모임·참여 탭 일정 참석, 커뮤니티 탭 |
| 라운드가 끝나면 | 요약 탭 90일: 완주, 첫 매출, 오리엔테이션 완료율 / 회원 탭 가입 월별 활동률 |

숫자는 판단의 출발점일 뿐입니다. 페이지뷰가 늘었는데 신청이 그대로라면 어디서 막히는지(콘텐츠 탭 '가입 신청까지')를 먼저 보고, 체크인 제출률이 떨어진 그룹은 숫자보다 그룹장과의 대화가 먼저입니다.

## 기술 메모

- 표: `analytics_events` (schema.sql v1.3). 첫 요청 때 자동으로 만들어집니다. 스크롤은 `scroll` 열(0~100, 머문 시간 기록에만)에 들어가고, 이미 운영 중인 DB에는 마이그레이션 `2026-11-19-analytics-scroll`이 열을 더합니다.
- 수집 API: `POST /api/t` — 한 번에 최대 20건, 잘못된 값은 버리고 항상 204로 답합니다.
- KPI API: `GET /api/admin/kpi/summary|traffic|content|members|groups|community?range=7|30|90|365` 또는 `?start=YYYY-MM-DD&end=YYYY-MM-DD` (운영진만). 콘텐츠에 `&path=/guide/…`를 붙이면 페이지 상세가 함께 옵니다.
- 목표·수집 설정: `PUT /api/admin/kpi/settings` (운영자만) — `{ targets: { visitors, views, apps, signups, active }, analytics: { enabled, start }, reason }`. 설정 표의 `kpi_targets`, `analytics`에 저장됩니다. 기본값은 `rules.js`의 `DEFAULT_SETTINGS`(수집 시작 2026-11-25).
- 코드: `functions/_lib/kpi-routes.js`(수집·집계), `public/app/views/admin/kpi.js`(화면), `public/assets/track.js`(브라우저 스크립트).
- 목표 기록: 가입 신청서 제출(`goal:apply`), 초대 코드 가입 완료(`goal:signup`). 다른 목표를 더하려면 그 동작이 끝나는 곳에서 `window.machalTrack.goal('이름', '설명')`을 부르면 됩니다.
