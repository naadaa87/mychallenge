# 마이챌린지 검색 노출(SEO) 운영 가이드

마이챌린지 홈페이지가 네이버·구글에서 잘 찾히도록 이미 해 둔 것, 공개 직후 할 일, 앞으로 글을 쓸 때 지킬 규칙을 정리했습니다.
검색량 숫자는 일부러 적지 않았습니다. 키워드별 검색량은 **네이버 검색광고 → 도구 → 키워드 도구**와 **네이버 데이터랩 → 검색어트렌드**에서 직접 확인하세요.

---

## 1. 이미 갖춰 둔 것

| 항목 | 내용 |
|---|---|
| 읽을 수 있는 주소 | 공개 페이지는 모두 실제 주소(`/about/`, `/guide/side-income-tax/`)를 가진 HTML입니다. 예전처럼 `#/` 주소가 아니라서 검색 로봇이 본문을 그대로 읽습니다 |
| 제목·설명 | 페이지마다 다른 `<title>`과 `meta description`(50~160자). 핵심 키워드를 앞쪽에 둠 |
| 대표 주소 | 모든 페이지에 `canonical`. 끝에 `/`가 붙은 주소 하나로 통일(없이 들어오면 308/301로 이동) |
| 공유 미리보기 | Open Graph·트위터 카드, 페이지별 1200×630 이미지(`public/og/`) — 카카오톡·네이버 블로그·페이스북 공유 시 표시 |
| 구조화 데이터 | Organization, WebSite, BreadcrumbList(모든 하위 페이지), Article(가이드·페이퍼), FAQPage(/faq/), CollectionPage(/guide/, /papers/) |
| 사이트맵 | `/sitemap.xml` — 공개 페이지 22개 + 외부 공개 페이퍼가 승인될 때마다 자동 추가 |
| RSS | `/rss.xml` — 가이드 11편 + 공개 페이퍼. 네이버 서치어드바이저 RSS 제출용 |
| robots.txt | 전체 허용, `/api/`만 제외, 사이트맵 위치 표시 |
| 회원 공간 제외 | `/app/`은 `noindex`(메타 태그 + `X-Robots-Tag`) — 로그인 화면이 검색 결과에 섞이지 않음 |
| 404 | 없는 주소는 실제 404 상태로 응답(검색엔진이 빈 페이지를 색인하지 않음) |
| 속도·접근성 | 정적 HTML, 이미지 없는 그래픽, 글꼴 1개. 로컬 Lighthouse 기준 SEO 100 · 접근성 95~100 · 성능 99(홈) |
| 소유확인 자리 | `functions/_site/config.js`의 `naverVerification`, `googleVerification`에 코드만 넣으면 모든 페이지에 메타 태그가 들어감 |

점검 도구: `npm run serve` 후 `npm run check:seo` — 모든 공개 페이지의 제목·설명 길이, h1 개수, canonical, OG, JSON-LD 문법, 내부 링크, 중복 제목·설명, robots·RSS·404를 확인합니다.

## 3. 공개 직후 체크리스트

### 3-1. 네이버 서치어드바이저 (https://searchadvisor.naver.com)
1. 네이버 아이디로 로그인 → **웹마스터 도구** → 사이트 등록에 대표 주소 입력 (예: `https://mychallenge.pages.dev`)
2. 소유확인 → **HTML 태그** 방식 선택 → 나온 태그의 `content="…"` 값만 복사
3. GitHub에서 `functions/_site/config.js` → `naverVerification: '복사한 값'` → Commit (또는 Cloudflare 환경 변수 `NAVER_SITE_VERIFICATION`) → 배포가 끝나면 서치어드바이저에서 **소유확인** 클릭
4. **요청 → 사이트맵 제출**: `https://대표주소/sitemap.xml`
5. **요청 → RSS 제출**: `https://대표주소/rss.xml`
6. **검증 → robots.txt**: 수집 요청 후 오류가 없는지 확인
7. **요청 → 웹 페이지 수집**: 홈, `/about/`, `/how-it-works/`, `/guide/` 와 가이드 글 몇 편을 하나씩 요청
8. **검증 → 웹 페이지 최적화**: 홈 주소를 넣어 제목·설명·OG 진단이 통과하는지 확인
9. 1~2주 뒤 **리포트 → 콘텐츠 노출/클릭**에서 수집·노출 여부 확인

### 3-2. 구글 서치콘솔 (https://search.google.com/search-console)
1. 속성 추가 → **URL 접두어**에 대표 주소 입력 (커스텀 도메인이 Cloudflare에 있다면 **도메인** 방식 + DNS 확인도 가능)
2. 확인 방법 **HTML 태그** → `content` 값을 `config.js`의 `googleVerification`에 넣고 배포 → 확인
3. **Sitemaps** 메뉴에 `sitemap.xml` 제출
4. **URL 검사**로 홈과 주요 페이지 색인 요청
5. 2~4주 뒤 **실적**에서 노출 검색어 확인 → 2장 키워드 지도와 비교

### 3-3. 그 밖의 검색엔진
- **Bing 웹마스터 도구**: 구글 서치콘솔에서 사이트를 가져오면 끝납니다. Bing 색인을 쓰는 다른 서비스에도 함께 노출됩니다.
- **다음(카카오)**: 다음 검색등록 페이지에서 사이트를 등록합니다.

### 3-4. 대표 주소를 바꿀 때
커스텀 도메인을 붙이면 `SITE_URL`(또는 `config.js`의 `url`)을 새 주소로 바꾸고, 네이버·구글에 **새 주소로 사이트를 다시 등록**합니다. 예전 `*.pages.dev` 주소에서 새 도메인으로 가는 301 이동은 Cloudflare **Bulk Redirects** 또는 Pages 프로젝트의 커스텀 도메인 설정으로 걸어 둡니다.

## 4. 글을 쓸 때 지킬 규칙

**제목**
- 대표 키워드를 앞에 둡니다: "부업 소득 세금 정리: 3.3%와 8.8%의 차이…"
- 25~40자. 사이트 이름은 자동으로 붙습니다(`| 마이챌린지`).
- 낚시성 문구("이것만 알면 월 300") 금지. 마챌 원칙과 광고 규정 모두에 어긋납니다.

**설명(description)**
- 70~120자. 이 글을 읽으면 무엇을 알게 되는지 한두 문장으로.
- 페이지마다 달라야 합니다(`check:seo`가 중복을 잡습니다).

**본문**
- `<h2>`로 4~7개 구간을 나누고, `toc`(차례)에 같은 id를 적습니다. h1은 자동으로 하나만 들어갑니다.
- 숫자에는 출처를 붙이고 `sources`에 링크를 남깁니다. 기사 문장을 그대로 옮기지 말고 숫자와 사실만 우리 말로 다시 씁니다.
- 내부 링크 2~3개: 관련 가이드, 그리고 `/how-it-works/` 또는 `/apply/`.
- 사람이 쓴 것처럼: "~에 대해 알아보겠습니다", "결론적으로", 같은 말 반복, 과한 강조를 피합니다. 실제 회원이 겪는 장면으로 시작하면 좋습니다.
- 법·세금 글은 맨 위에 "일반 정보이며 전문가 확인을 권한다"는 문장과 기준 시점을 적습니다.
- "수익 보장", "전액 환급", "누구나 월 ○○만 원" 같은 표현은 쓰지 않습니다.

**주소(slug)**
- 영문 소문자와 하이픈: `side-income-tax`. 한 번 공개한 slug는 바꾸지 않습니다.
- 꼭 바꿔야 하면 `public/_redirects` 파일에 `/guide/옛-주소/ /guide/새-주소/ 301` 한 줄을 추가합니다.

**고친 날**
- 내용을 크게 고치면 `modified` 날짜를 바꿉니다. 사이트맵 `lastmod`와 글 상단 "고친 날"에 반영되어 검색엔진이 다시 읽어 갑니다.

**공유 이미지**
- 새 글을 쓰면 컴퓨터에서 `node scripts/render-og.mjs`로 `public/og/guide-<slug>.png`를 만들어 함께 올립니다(없으면 기본 이미지).

## 6. 사이트 밖에서 할 일

- **프로젝트 페이퍼**: 외부 공개 페이퍼가 쌓일수록 `/papers/`가 "사이드프로젝트 사례"류 검색에서 힘을 얻습니다. 라운드가 끝날 때마다 그룹에 외부 공개 동의를 요청하세요.
- **네이버 블로그·카페, 브런치**: 원문은 홈페이지에 두고, 외부 채널에는 요약과 링크를 올립니다. 같은 글 전문을 여러 곳에 올리면 원문보다 블로그가 먼저 노출될 수 있습니다.
- **카카오톡 공유**: 모든 페이지에 공유 이미지가 있으니 링크만 붙여도 미리보기가 나옵니다.
- **분기 사례집**: PDF로 내더라도 같은 내용을 페이퍼 페이지로도 공개해 두면 검색으로 들어옵니다.

## 7. 측정

- 네이버: 서치어드바이저 **리포트**(노출·클릭·수집 현황)
- 구글: 서치콘솔 **실적**(검색어별 노출·클릭·평균 순위)
- 방문 통계가 필요하면 Cloudflare Pages 프로젝트에서 **Web Analytics**를 켭니다. 쿠키를 쓰지 않는 방식이라 개인정보처리방침을 고치지 않아도 됩니다.
- 가장 중요한 숫자는 결국 **가입 신청 수**입니다. 운영본부 → CSV 내려받기(가입 신청)로 월별 신청 수를 보고, 신청서의 "추천인"·"질문" 칸으로 어디서 알게 됐는지 함께 확인하세요.

## 8. 하지 말 것

- 키워드를 본문에 억지로 반복하기, 흰 글씨로 숨기기
- 다른 사이트 글을 베끼거나 짜깁기하기(출처를 달아도 전문 복사는 안 됩니다)
- 이미 공개한 주소를 301 없이 바꾸거나 지우기
- 회원 공간(`/app/`) 화면을 공개 페이지처럼 링크로 퍼뜨리기 — 로그인 화면만 보입니다
- 같은 주제로 비슷한 글 여러 편 쓰기

## 9. 색인이 안 될 때 확인할 것

1. 주소를 브라우저에서 열면 200으로 열리는가 (없는 페이지는 404)
2. 페이지 소스에 `noindex`가 없는가 (회원 공간 외에는 없어야 정상)
3. `canonical`이 그 페이지 자신의 주소인가 (다른 도메인으로 되어 있다면 `SITE_URL` 설정 확인)
4. `/robots.txt`가 열리고 `Disallow: /`가 없는가
5. 사이트맵에 그 주소가 들어 있는가
6. 서치어드바이저 **웹 페이지 수집**, 서치콘솔 **URL 검사**로 직접 요청
7. 공개한 지 2주가 안 됐다면 기다리기. 새 사이트는 처음 색인까지 시간이 걸립니다.
