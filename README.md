# 마이챌린지(마챌) 홈페이지

함께 배우고 함께 도전하는 사이드프로젝트 커뮤니티 **마이챌린지(My Challenge, 줄여서 마챌)**의 홈페이지입니다.
정기모임에서 사업 아이디어·시장·트렌드·AI 활용·사이드프로젝트를 함께 살펴보고, 승인받은 그룹리더가 만든 **학습그룹·도전그룹**에서 목표에 도전하고, 기록과 성과를 커뮤니티와 **성과발표회**에서 나눕니다.
검색엔진이 읽는 **공개 사이트**와 회원이 쓰는 **회원 공간(/app/)** 두 부분으로 되어 있습니다.

| 구분 | 주소 | 내용 |
|---|---|---|
| 공개 사이트 | `/`, `/about/`, `/how-it-works/`, `/goals/`(수익목표), `/levels/`, `/programs/`, `/faq/`, `/apply/`, `/guide/…`, `/privacy/`, `/terms/` | 미리 만들어 둔 HTML. 제목·설명·OG·구조화 데이터·사이트맵이 갖춰져 있어 네이버·구글이 그대로 읽습니다 |
| 프로젝트 페이퍼 | `/papers/`, `/papers/12/` | 외부 공개로 승인된 페이퍼 요약을 서버에서 그려서 보여 줍니다 (검색 노출용) |
| 회원 공간 | `/app/#/login`, `/app/#/dashboard`, `/app/#/groups` … | 가입·그룹(모임·출석·기록·목표·성과)·정기모임·커뮤니티·페이퍼·운영본부 화면. 검색엔진에는 노출하지 않습니다(noindex) |
| 검색엔진용 | `/sitemap.xml`, `/rss.xml`, `/robots.txt` | 사이트맵(공개 페이퍼 자동 포함), RSS(가이드 + 페이퍼), 크롤러 안내 |

기획 문서(MC-01~05, 통합 기획서 v2.0)는 `docs/` 폴더에 있고, 검색 노출 운영 방법은 **[docs/SEO-가이드.md](docs/SEO-가이드.md)**, 운영본부 콘솔 사용법은 **[docs/운영본부-가이드.md](docs/운영본부-가이드.md)**, 그룹리더용 안내는 **[docs/그룹리더-가이드.md](docs/그룹리더-가이드.md)**, v2.0 운영 모델과 근거는 **[docs/운영모델-v2.md](docs/운영모델-v2.md)**, KPI 지표의 정의는 **[docs/KPI-정의.md](docs/KPI-정의.md)**에 정리했습니다. `docs/*.docx` 기획 문서는 v1(라운드·합의서·수익 배분) 기준의 기록이며, 지금 운영 방식은 v2.0 문서를 따릅니다.

```
public/                 Cloudflare Pages가 그대로 내보내는 폴더
  index.html, about/, guide/ …   ← 공개 사이트 (scripts/build-site.mjs 가 만든 결과물)
  assets/site.css, site.js       ← 공개 사이트 디자인·편의 기능
  assets/track.js                ← 방문·클릭·머문 시간 기록 (공개 사이트·회원 공간 공통)
  assets/img/*.webp              ← 일러스트·아이콘 (scripts/make_images.py 로 생성, 배치는 functions/_site/art.js·pages.js)
  app/                           ← 회원 공간 (index.html, app.js, core.js, styles.css, views/*.js)
  app/views/group.js             ← 그룹 목록·만들기·그룹 공간(홈·모임·출석·기록·목표·성과·그룹원·설정·페이퍼)
  admin/                         ← 운영본부 (https://mychallenge.kr/admin) 입구: 로그인 화면과 주소 처리
  app/views/admin/               ← 운영본부 화면 (현황·KPI 지표·받은 일·사람·그룹·소통·총괄 관리)
  og/*.png, icon-*.png           ← 공유 미리보기 이미지·아이콘 (scripts/render-og.mjs 로 생성)
  _routes.json, _headers, _redirects, robots.txt, site.webmanifest, 404.html
functions/
  api/[[path]].js       ← 모든 /api/* 처리 (회원·정기모임·커뮤니티·페이퍼 등)
  papers/[[path]].js    ← /papers/ 공개 페이퍼 페이지
  sitemap.xml.js, rss.xml.js
  _site/                ← 공개 사이트 원고와 레이아웃 (config.js, pages.js, guides.js, legal.js …)
  _lib/                 ← 규칙 기본값(rules.js), 그룹·출석 API(group-routes.js), 공통 유틸, 운영본부 API(admin-routes.js), 이용 통계·KPI API(kpi-routes.js)
scripts/                ← build-site.mjs (공개 페이지 생성), render-og.mjs (OG 이미지 생성)
schema.sql              ← D1(SQLite) 테이블 정의
tests/                  ← 테스트·로컬 미리보기·SEO 점검
docs/                   ← 기획 문서와 SEO 가이드
```

## 1. 배포하기 (GitHub → Cloudflare Pages + D1)

터미널 없이 브라우저만으로 끝낼 수 있습니다.

### 1-1. D1 데이터베이스 만들기
1. Cloudflare 대시보드 → **Storage & Databases → D1 SQL Database → Create**
2. 이름: `machal-db` → Create
3. 표는 따로 만들 필요가 없습니다. 홈페이지가 처음 API 요청을 받을 때 `schema.sql`의 표를 자동으로 만들고, 모자란 표가 있으면 채웁니다(v1.0에서 올라온 경우에도 v1.1 표가 자동 추가됩니다).
   - 직접 만들고 싶다면 DB의 **Console** 탭에 `schema.sql` 내용을 붙여 넣고 실행해도 됩니다. 모두 "IF NOT EXISTS"라 여러 번 실행해도 안전합니다.

### 1-2. Pages 프로젝트 만들기
1. **Workers & Pages → Create → Pages → Connect to Git** → 저장소 `mychallenge` 선택
2. 빌드 설정
   - Framework preset: **None**
   - Build command: **`node scripts/build-site.mjs`** (권장 — 비워 두어도 저장소에 들어 있는 결과물로 동작합니다)
   - Build output directory: **`public`**
3. **Save and Deploy**

> Build command를 넣어 두면, GitHub에서 글(`functions/_site/guides.js`)이나 설정(`config.js`)을 고칠 때마다 공개 페이지가 자동으로 다시 만들어집니다. 빌드는 저장소의 `.node-version`에 따라 Node 22로 돌아갑니다.
> 저장소에는 `wrangler.toml`을 두지 않았습니다(참고용은 `wrangler.example.toml`). 이 파일이 있으면 Pages가 대시보드의 D1 연결 대신 파일 설정을 따르기 때문입니다.

### 1-3. D1 연결 (중요)
1. Pages 프로젝트 → **Settings → Bindings → Add → D1 database**
2. Variable name: **`DB`** (대문자 그대로), D1 database: `machal-db`
3. **Deployments 탭 → 최신 배포 → Retry deployment** (바인딩은 다시 배포해야 적용됩니다)

### 1-4. 첫 총괄관리자 계정
1. 배포된 주소 뒤에 **`/app/`** 을 붙여 엽니다. 예: `https://mychallenge.kr/app/`
2. 계정이 하나도 없으면 자동으로 **초기 설정 화면**이 뜹니다. 이름·이메일·비밀번호를 넣으면 **마스터(L5)·운영진** 계정이 만들어집니다.
3. 이 화면은 첫 계정이 생기면 닫히고, 이 계정이 **총괄관리자**가 됩니다. 운영본부는 **`/admin`** (예: `https://mychallenge.kr/admin`)에서 엽니다. 다른 운영진은 **운영본부 → 운영진·권한**에서 회원 이메일로 지정하고 담당 영역을 정합니다.

### 1-5. 대표 주소 맞추기
- Pages 기본 주소가 `https://mychallenge.kr`가 아니거나 커스텀 도메인을 연결했다면, 아래 둘 중 하나로 대표 주소를 알려 주세요. 검색엔진에 알려 주는 정식 주소(canonical), 사이트맵, 공유 이미지 주소가 모두 이 값을 씁니다.
  - **방법 A (권장)**: Pages → Settings → **Variables and Secrets** → `SITE_URL` = `https://내도메인` 추가 → 다시 배포 (Build command가 설정되어 있어야 공개 페이지에도 반영됩니다)
  - **방법 B**: GitHub에서 `functions/_site/config.js`의 `url` 값을 고치고 Commit
- 커스텀 도메인: Pages 프로젝트 → **Custom domains → Set up a custom domain**

### 1-6. 정식 공개 전에 꼭 할 일
1. `functions/_site/config.js`의 **`operator`** 칸을 채웁니다: 운영 법인·대표·사업자등록번호·주소·문의 이메일·**개인정보 보호책임자**. 비어 있으면 개인정보처리방침에 "〔운영 개시 전 게시〕"로 표시됩니다.
2. `/privacy/`(개인정보처리방침)와 `/terms/`(이용약관)는 기획서 기준 초안입니다. **법률 전문가 검토**를 받고, 고친 날짜를 `config.js`의 `policyVersion`에 적습니다(가입 동의 기록에 이 값이 남습니다).
3. 네이버 서치어드바이저·구글 서치콘솔 등록 → [docs/SEO-가이드.md](docs/SEO-가이드.md)의 체크리스트대로 진행합니다.

## 2. 글과 문구 고치기

### 일러스트 바꾸기
- 그림 파일은 `public/assets/img/`에 있고, 어느 페이지에 어떤 그림이 들어가는지는 `functions/_site/pages.js`(페이지별)와 `functions/_site/art.js`(가이드 표지, 등급·배지·분야 아이콘)에 적혀 있습니다.
- 같은 이름의 `.webp` 파일로 바꿔 넣고 push하면 됩니다. 비율은 활동 장면 16:10, 페이지 머리 그림 1:1에 가깝게 맞춰 주세요. 그림 크기가 달라졌다면 `functions/_site/images.generated.js`의 가로·세로 숫자도 같이 고칩니다.
- 원본(구글 드라이브 '마이챌린지 이미지' 폴더)에서 한꺼번에 다시 만들 때는 `python3 scripts/make_images.py <원본 폴더>`를 씁니다.


| 고칠 것 | 파일 | 비고 |
|---|---|---|
| 가이드 글 추가·수정 | `functions/_site/guides.js` | 배열 맨 앞에 새 글을 넣습니다. `slug`는 주소이므로 한 번 정하면 바꾸지 않습니다 |
| 홈·소개·함께하는 방식·수익목표·등급·프로그램·FAQ·가입 신청 | `functions/_site/pages.js` | |
| 개인정보처리방침·이용약관 | `functions/_site/legal.js` | |
| 대표 주소·소유확인 코드·운영 주체·단체카톡방 주소 | `functions/_site/config.js` | 단체카톡방 주소는 운영본부 → 단체카톡방 → 설정에서 바꿉니다 (`communityChat.url`은 처음 기본값) |
| 머리글·바닥글 메뉴 | `functions/_site/layout.js` | |
| 디자인 | `public/assets/site.css` (공개), `public/app/styles.css` (회원) | 포인트 컬러 `--blue: #2457F5` |

GitHub 웹에서 파일 → 연필 아이콘 → 수정 → Commit changes. Build command를 설정해 두었다면 몇 분 뒤 사이트에 반영됩니다.
Build command를 비워 두었다면 컴퓨터에서 `node scripts/build-site.mjs`를 실행하고 바뀐 `public/` 파일까지 함께 올려야 합니다.

새 가이드를 쓰면 공유 이미지도 만들어 두는 게 좋습니다: `node scripts/render-og.mjs` (크롬 필요). 이미지가 없으면 기본 이미지가 쓰입니다.

## 3. 처음 운영하는 순서

1. **운영본부 → 규칙 설정**에서 그룹 규칙(기본 정원, 그룹리더·회원이 동시에 맡는 그룹 수)과 **출석 규칙 기본값**, 포인트, 승급 조건을 확인합니다. (바꾸는 것은 운영자만, 이유를 함께 남깁니다)
2. **운영본부 → 시즌**에서 "2027년 봄 시즌"처럼 시즌을 만들고 상태를 **신규 회원 모집**으로 두면 홈페이지 첫 화면과 가입 신청 페이지에 모집 안내가 뜹니다. 그룹은 시즌과 관계없이 언제든 만들 수 있습니다.
3. **운영본부 → 정기모임·일정**에서 정기모임을 등록합니다. 유형(정기모임·성과발표회·세미나·워크숍·오피스아워·네트워킹), 방식(오프라인·온라인·온·오프라인), 온라인 링크, 다룰 주제를 고릅니다. 공개 사이트 `/programs/`에도 자동으로 표시됩니다.
4. 홈페이지의 **가입 신청**(`/apply/`)을 안내하고, **운영본부 → 가입 신청**에서 승인해 초대 코드를 보냅니다. 회원은 초대 코드로 가입 → 오리엔테이션 → 챌린저(L1)가 되면 바로 그룹에 참여할 수 있습니다.
5. 그룹을 이끌 회원은 **내 정보 → 그룹리더**에서 신청합니다. **운영본부 → 그룹리더 신청**에서 승인하면 그 회원은 언제든 그룹을 만들 수 있습니다. 믿을 만한 회원은 **회원 상세 → 그룹리더 자격 주기**로 신청 없이 바로 지정할 수도 있습니다.
6. 그룹리더가 **그룹 → 그룹 만들기**에서 학습그룹·도전그룹을 만들면 바로 모집이 시작됩니다. 목표·마일스톤·모임 주기·정원·참여 방식·출석 규칙을 그룹리더가 정합니다.
7. 그룹리더는 **모임·출석** 탭에서 일정을 잡고(몇 주치를 한 번에), 모임이 시작되면 **출석 받기**로 4자리 코드를 띄웁니다. 그룹원은 코드를 입력하고, 모임이 끝나면 **출석 마감**. 마감하지 않은 모임은 끝나고 12시간 뒤 자동으로 마감됩니다. 출석 규칙에 따라 경고와 퇴출 기준이 자동으로 적용됩니다.
8. 정기모임마다 회원의 **발제 신청**과 성과발표회의 **그룹 발표 신청**이 **운영본부 → 발표 신청**에 모입니다. 확정하고, 발표가 끝나면 "발표함"을 눌러 포인트를 줍니다.
9. 도전그룹이 매출을 기록하면 **운영본부 → 매출 확인**에서 증빙을 보고 확인합니다. 확인하면 그룹원 모두에게 첫 매출 배지가 나갑니다.
10. 그룹리더가 그룹을 마치면 출석 기준을 채운 그룹원은 '그룹 완주' 배지를 받고, 그룹리더가 **프로젝트 페이퍼**를 냅니다. **운영본부 → 페이퍼 검토**에서 승인하면 외부 공개 페이퍼는 `/papers/`와 사이트맵·RSS에 올라갑니다.
    - **운영본부 → 현황**의 '주의가 필요한 그룹'과 **그룹 현황**(순조·주의·위험)으로 모임이 끊긴 그룹, 출석을 받지 않은 모임, 출석률이 낮은 그룹, 퇴출 기준에 닿은 그룹원을 매주 확인합니다.
    - 그룹에서 퇴출된 회원의 이의는 **운영본부 → 이의·신고**에 올라오고, 필요하면 그룹 상세에서 복귀시킵니다.

### 운영본부의 데이터 관리
- **운영본부 → 데이터·백업**: 그룹, 그룹원, 그룹 모임, 모임 출석, 성과 기록, 페이퍼, 포인트 CSV는 운영진 누구나, 회원·가입 신청·동의 기록 CSV와 전체 백업(JSON)은 운영자만 받습니다. 받은 기록은 감사 로그에 남습니다.
- 가입하지 않은 신청서는 처리 후 6개월이 지나면 운영 현황을 열 때 자동으로 파기됩니다(개인정보처리방침 2항).
- 회원 탈퇴는 회원이 **내 정보 → 회원 탈퇴**에서 직접 합니다. 개인정보는 지우고, 그룹에 함께 남긴 출석·기록·성과는 이름 없이 남깁니다. 진행 중인 그룹을 이끄는 그룹리더는 그룹을 마치거나 리더를 바꾼 뒤 탈퇴할 수 있습니다.

## 5. 규칙을 바꾸고 싶을 때

- **숫자·조건**: 운영본부 → 규칙 설정(총괄관리자만). 출석 규칙 기본값은 새로 만드는 그룹에만 쓰이고, 이미 있는 그룹은 그룹리더가 정한 값을 그대로 씁니다. 공개 사이트의 `/levels/`는 설정값을 불러와 표시합니다.

- **수익을 나누는 방식**: v2.0에서 뺐습니다. 실제 수익이 나는 그룹이 생기면 그 그룹과 함께 정하고 `/goals/`에 먼저 공개합니다.

## 6. 알아 둘 점

- 비밀번호는 PBKDF2-SHA256(100,000회)으로 저장하고, 세션은 HttpOnly 쿠키입니다. 모든 권한 검사는 서버에서 합니다.
- 같은 이메일로 15분 안에 10번(같은 IP는 30번) 로그인에 실패하면 15분 동안 막습니다.
- 공개 페이지는 `machal_in` 표시 쿠키로만 로그인 여부를 알아내므로, 페이지를 볼 때마다 API를 부르지 않습니다. `_routes.json`으로 Functions는 `/api/*`, `/papers/*`, `/sitemap.xml`, `/rss.xml`에서만 실행됩니다(무료 요청 한도 절약).
- 이메일 자동 발송은 없습니다. 초대 코드·알림은 화면에 표시되고, 운영본부가 이메일/카톡으로 전달합니다.
- 매출 증빙은 링크나 설명으로 받고 운영진만 봅니다. 계좌번호·고객 개인정보는 가리고 올리도록 안내합니다.
- 예전 주소 `/rules/`, `/guide/profit-sharing/`는 `public/_redirects`로 `/goals/`에 301 이동합니다. 회원 공간의 예전 `#/challenges/…`, `#/settlements/…` 주소는 그룹 화면으로 옮겨 갑니다.
