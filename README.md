# 마이챌린지(마챌) 홈페이지

사이드프로젝트 수익 도전 모임 **마이챌린지(My Challenge, 줄여서 마챌)**의 운영 홈페이지입니다.
기획 문서(MC-01~05, `docs/` 폴더)에 적힌 규칙을 그대로 코드로 옮겼습니다.

- 가입 신청 → 운영본부 승인 → 초대 코드 가입 → 오리엔테이션(원칙 3개 확인)
- 6단계 등급(L0 게스트 ~ L5 마스터), 활동 포인트와 하루 상한, L2 자동 승급, L3 이상 신청·심사
- 챌린지 제안 → 6항목 심사표(45점 만점, 27점 통과) → 모집 → **합의서 전원 서명 → 운영본부 승인** → 진행
- 그룹 공간: 주간 체크인, 완료 기록(그룹장 확인), 장부, 마일스톤, 기여율 자동 산정(±10%p 조정)
- 정산 계산기: 매출−비용 → 분담금 회수 → 선지원 회수 → 대행 수수료 → 운영본부/그룹장/그룹원 풀, 최소 정산 이월, 3.3% 원천징수 참고액, 전원 확인·이의·운영본부 검수·지급 처리
- 프로젝트 페이퍼: 장부·체크인 숫자 자동 채움, 비공개 항목 선택, 등급별 열람(요약 L1 / 전문 L3), 승인 뒤에만 정산 지급
- 커뮤니티(질문·공유·후기·품앗이·공지), 일정과 출석 코드, 알림, 회원·첫 매출 명단
- 운영본부 화면: 처리 큐, KPI, 가입·심사·합의서·정산·페이퍼·승급·이의 처리, 회원 관리, **규칙 설정(코드 수정 없이 변경)**, 감사 로그

빌드 도구가 없습니다. HTML/CSS/JS 파일 그대로 올리면 됩니다.

```
public/            화면 (index.html, app.js, core.js, styles.css, views/*.js)
functions/api/     API (Cloudflare Pages Functions) — [[path]].js 한 파일이 모든 /api/* 를 처리
functions/_lib/    규칙 기본값(rules.js), 정산 계산기(settlement.js), 공통 유틸(util.js)
schema.sql         D1(SQLite) 테이블 정의
wrangler.toml      Cloudflare 설정
tests/             로컬 테스트·미리보기 (node 22 이상)
docs/              기획 문서 5종 (Word)
```

## 1. 배포하기 (GitHub → Cloudflare Pages + D1)

honplace와 같은 방식입니다. 터미널 없이 브라우저만으로 끝낼 수 있습니다.

### 1-1. GitHub에 올리기
1. GitHub에서 새 저장소를 만듭니다. 예: `machal` (Private 권장)
2. 이 폴더의 파일을 전부 올립니다. (GitHub 웹에서 "Add file → Upload files"로 폴더째 끌어다 놓아도 됩니다. `tests/.tmp`, `node_modules`는 올리지 않습니다.)

### 1-2. D1 데이터베이스 만들기
1. Cloudflare 대시보드 → **Storage & Databases → D1 SQL Database → Create**
2. 이름: `machal-db` → Create
3. 만들어진 DB의 **Console** 탭을 열고, 이 저장소의 `schema.sql` 내용을 전부 붙여 넣고 **Execute**
   - "CREATE TABLE IF NOT EXISTS"라서 여러 번 실행해도 괜찮습니다.

### 1-3. Pages 프로젝트 만들기
1. Cloudflare 대시보드 → **Workers & Pages → Create → Pages → Connect to Git**
2. 위에서 만든 GitHub 저장소 선택
3. 빌드 설정
   - Framework preset: **None**
   - Build command: *(비워 둠)*
   - Build output directory: **`public`**
4. **Save and Deploy**

### 1-4. D1 바인딩 연결 (중요)
1. Pages 프로젝트 → **Settings → Bindings → Add → D1 database**
2. Variable name: **`DB`** (대문자, 정확히 이 이름)
3. D1 database: `machal-db`
4. 저장한 뒤 **Deployments 탭에서 최신 배포를 Retry deployment** (바인딩은 재배포해야 적용됩니다)

> `wrangler.toml`의 `database_id`는 비워 두어도 됩니다. 대시보드에서 바인딩을 연결하면 그쪽이 우선입니다.
> wrangler CLI를 쓴다면 `npx wrangler d1 execute machal-db --remote --file=schema.sql` 로 스키마를 넣을 수 있습니다.

### 1-5. 첫 운영자 계정
1. 배포된 주소(예: `https://machal.pages.dev`)를 열면 자동으로 **초기 설정 화면**(`/#/setup`)으로 갑니다.
2. 이름·이메일·비밀번호를 넣으면 **마스터(L5)·운영진** 계정이 만들어지고 바로 운영본부 화면으로 들어갑니다.
3. 이 화면은 첫 계정이 생기면 닫힙니다. 다른 운영진은 **운영본부 → 회원 → 관리**에서 "운영진" 권한을 주면 됩니다.

### 1-6. 커스텀 도메인 (선택)
Pages 프로젝트 → **Custom domains → Set up a custom domain**. 도메인이 Cloudflare에 있으면 자동으로 연결됩니다.

## 2. 첫 라운드 운영 순서

1. **운영본부 → 규칙 설정**에서 최소 정산 금액, 예산 상한, 포인트, 승급 조건을 확인합니다. (기본값은 MC-03·MC-04 그대로)
2. **운영본부 → 라운드**에서 "2026 라운드 1" 같은 라운드를 만들고 상태를 **모집**으로 둡니다.
3. **운영본부 → 일정**에서 마챌데이·세미나를 등록합니다. 출석 코드는 자동 생성되며 운영진만 볼 수 있습니다.
4. 홈페이지의 **가입 신청**을 안내합니다. 신청이 오면 **운영본부 → 가입 신청**에서 승인하면 초대 코드가 나오고, 보낼 이메일 문안이 함께 뜹니다.
5. 회원은 초대 코드로 가입 → 오리엔테이션 → 챌린저(L1). 자기 자산 진단, 모임 참석, 포인트 300점이 차면 **자동으로 메이커(L2)**가 됩니다.
   - 첫 라운드는 리더가 없으므로 운영본부가 믿을 만한 회원을 **회원 관리 → 등급 조정**으로 리더(L4)로 올리거나, 운영진이 직접 **오피셜 챌린지**를 만듭니다.
6. 리더가 챌린지를 제안하면 **운영본부 → 챌린지 심사**에서 6항목 점수를 매깁니다. 27점 이상이면 승인 → 모집.
7. 그룹장이 그룹원을 수락하고 "모집 마감 → 합의서"를 누르면 합의서를 작성합니다. 전원이 서명하면 **운영본부 → 합의서 승인**에 올라오고, 승인하면 챌린지가 **진행 중**으로 바뀌며 4·7·8·12주차 마일스톤이 생깁니다.
8. 매주 그룹장이 체크인을 열고, 그룹원은 3분 체크인을 제출합니다. 완료 기록은 그룹장이 확인해야 포인트·기여도에 반영됩니다.
9. 라운드 말: 그룹장이 **기여율 확정 → 정산표 생성**. 그룹원 전원 확인 → 그룹장이 **페이퍼 제출** → 운영본부가 **페이퍼 승인** → **정산 검수 승인** → 지급표 확정 → 그룹장이 지급 완료 처리.
10. 데모데이 후 **운영본부 → 챌린지(또는 회원 관리)**에서 완주 처리하면 완주 배지가 부여되고, 메이커는 어치버 승급을 신청할 수 있습니다.

## 3. 로컬에서 미리 보기·테스트 (선택)

Node 22.5 이상이 필요합니다. 설치할 패키지는 없습니다.

```bash
npm test                      # 정산 계산기 6개 케이스 + 전체 흐름 API 테스트
node tests/serve.js           # http://localhost:8788 로컬 서버 (D1 대신 node:sqlite 사용)
MACHAL_DB=tests/.tmp/dev.sqlite node tests/api.test.js   # 미리보기용 샘플 데이터 채우기
node tests/screenshots.js     # 헤드리스 크롬으로 주요 화면 캡처 (google-chrome 필요)
```

wrangler로 실제 D1 로컬 환경을 쓰려면 `npm run db:local` 후 `npm run dev`.

## 4. 규칙을 바꾸고 싶을 때

- **숫자·비율·조건**: 운영본부 → 규칙 설정 (JSON 값). 바뀐 값은 즉시 적용되지만, 이미 승인된 합의서에는 당시 값이 저장되어 있어 소급되지 않습니다.
- **기본값 자체**: `functions/_lib/rules.js`
- **정산 공식**: `functions/_lib/settlement.js` (순수 함수, `tests/settlement.test.js`로 검증)
- **화면 문구·디자인**: `public/views/*.js`, `public/styles.css` (포인트 컬러 `--blue: #2457F5`)

## 5. 알아 둘 점

- 비밀번호는 PBKDF2-SHA256(100,000회)으로 저장하고, 세션은 HttpOnly 쿠키입니다. 모든 권한 검사는 서버(API)에서 합니다.
- 이메일 자동 발송은 없습니다. 초대 코드·알림은 화면에 표시되고, 운영본부가 이메일/카톡으로 전달합니다. (필요하면 Resend 같은 서비스를 Functions에 붙일 수 있습니다.)
- 파일 업로드(영수증 사진 등)는 링크로 받습니다. 구글 드라이브·노션 링크를 증빙 칸에 넣는 방식입니다.
- 정산표의 원천징수 3.3%는 **참고용 표시**입니다. 실제 세무 처리는 지급 주체가 확인합니다.
