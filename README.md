# 마이챌린지(마챌) 홈페이지

사이드프로젝트 수익 도전 모임 **마이챌린지(My Challenge, 줄여서 마챌)**의 홈페이지입니다.
검색엔진이 읽는 **공개 사이트**와 회원이 쓰는 **회원 공간(/app/)** 두 부분으로 되어 있습니다.

| 구분 | 주소 | 내용 |
|---|---|---|
| 공개 사이트 | `/`, `/about/`, `/how-it-works/`, `/rules/`, `/levels/`, `/programs/`, `/faq/`, `/apply/`, `/guide/…`, `/privacy/`, `/terms/` | 미리 만들어 둔 HTML. 제목·설명·OG·구조화 데이터·사이트맵이 갖춰져 있어 네이버·구글이 그대로 읽습니다 |
| 프로젝트 페이퍼 | `/papers/`, `/papers/12/` | 외부 공개로 승인된 페이퍼 요약을 서버에서 그려서 보여 줍니다 (검색 노출용) |
| 회원 공간 | `/app/#/login`, `/app/#/dashboard` … | 가입·챌린지·체크인·장부·합의서·정산·페이퍼·운영본부 화면. 검색엔진에는 노출하지 않습니다(noindex) |
| 검색엔진용 | `/sitemap.xml`, `/rss.xml`, `/robots.txt` | 사이트맵(공개 페이퍼 자동 포함), RSS(가이드 + 페이퍼), 크롤러 안내 |

기획 문서(MC-01~05, 통합 기획서 v2.0)는 `docs/` 폴더에 있고, 검색 노출 운영 방법은 **[docs/SEO-가이드.md](docs/SEO-가이드.md)**, 운영본부 콘솔 사용법은 **[docs/운영본부-가이드.md](docs/운영본부-가이드.md)**에 정리했습니다.

```
public/                 Cloudflare Pages가 그대로 내보내는 폴더
  index.html, about/, guide/ …   ← 공개 사이트 (scripts/build-site.mjs 가 만든 결과물)
  assets/site.css, site.js       ← 공개 사이트 디자인·편의 기능
  app/                           ← 회원 공간 (index.html, app.js, core.js, styles.css, views/*.js)
  app/views/admin/               ← 운영본부 콘솔 (현황·받은 일·사람·챌린지·돈·소통·설정)
  og/*.png, icon-*.png           ← 공유 미리보기 이미지·아이콘 (scripts/render-og.mjs 로 생성)
  _routes.json, _headers, robots.txt, site.webmanifest, 404.html
functions/
  api/[[path]].js       ← 모든 /api/* 처리 (회원·챌린지·정산 등)
  papers/[[path]].js    ← /papers/ 공개 페이퍼 페이지
  sitemap.xml.js, rss.xml.js
  _site/                ← 공개 사이트 원고와 레이아웃 (config.js, pages.js, guides.js, legal.js …)
  _lib/                 ← 규칙 기본값, 정산 계산기, 공통 유틸, 운영본부 API(admin-routes.js)
scripts/                ← build-site.mjs (공개 페이지 생성), render-og.mjs (OG 이미지 생성)
schema.sql              ← D1(SQLite) 테이블 정의
tests/                  ← 테스트·로컬 미리보기·SEO 점검
docs/                   ← 기획 문서와 SEO 가이드
```

## 1. 배포하기 (GitHub → Cloudflare Pages + D1)

터미널 없이 브라우저만으로 끝낼 수 있습니다.

### 1-1. D1 데이터베이스 만들기
1. Cloudflare 대시보드 → **Storage & Databases → D1 SQL Database → Create**
2. 이름: `machal-db` → Create
3. 표는 따로 만들 필요가 없습니다. 홈페이지가 처음 API 요청을 받을 때 `schema.sql`의 표를 자동으로 만들고, 모자란 표가 있으면 채웁니다(v1.0에서 올라온 경우에도 v1.1 표가 자동 추가됩니다).
   - 직접 만들고 싶다면 DB의 **Console** 탭에 `schema.sql` 내용을 붙여 넣고 실행해도 됩니다. 모두 "IF NOT EXISTS"라 여러 번 실행해도 안전합니다.

### 1-2. Pages 프로젝트 만들기
1. **Workers & Pages → Create → Pages → Connect to Git** → 저장소 `mychallenge` 선택
2. 빌드 설정
   - Framework preset: **None**
   - Build command: **`node scripts/build-site.mjs`** (권장 — 비워 두어도 저장소에 들어 있는 결과물로 동작합니다)
   - Build output directory: **`public`**
3. **Save and Deploy**

> Build command를 넣어 두면, GitHub에서 글(`functions/_site/guides.js`)이나 설정(`config.js`)을 고칠 때마다 공개 페이지가 자동으로 다시 만들어집니다. 빌드는 저장소의 `.node-version`에 따라 Node 22로 돌아갑니다.
> 저장소에는 `wrangler.toml`을 두지 않았습니다(참고용은 `wrangler.example.toml`). 이 파일이 있으면 Pages가 대시보드의 D1 연결 대신 파일 설정을 따르기 때문입니다.

### 1-3. D1 연결 (중요)
1. Pages 프로젝트 → **Settings → Bindings → Add → D1 database**
2. Variable name: **`DB`** (대문자 그대로), D1 database: `machal-db`
3. **Deployments 탭 → 최신 배포 → Retry deployment** (바인딩은 다시 배포해야 적용됩니다)

### 1-4. 첫 운영자 계정
1. 배포된 주소 뒤에 **`/app/`** 을 붙여 엽니다. 예: `https://mychallenge.pages.dev/app/`
2. 운영자가 없으면 자동으로 **초기 설정 화면**이 뜹니다. 이름·이메일·비밀번호를 넣으면 **마스터(L5)·운영진** 계정이 만들어집니다.
3. 이 화면은 첫 계정이 생기면 닫힙니다. 다른 운영진은 **운영본부 → 회원 → 관리**에서 "운영진" 권한을 주면 됩니다.

### 1-5. 대표 주소 맞추기
- Pages 기본 주소가 `https://mychallenge.pages.dev`가 아니거나 커스텀 도메인을 연결했다면, 아래 둘 중 하나로 대표 주소를 알려 주세요. 검색엔진에 알려 주는 정식 주소(canonical), 사이트맵, 공유 이미지 주소가 모두 이 값을 씁니다.
  - **방법 A (권장)**: Pages → Settings → **Variables and Secrets** → `SITE_URL` = `https://내도메인` 추가 → 다시 배포 (Build command가 설정되어 있어야 공개 페이지에도 반영됩니다)
  - **방법 B**: GitHub에서 `functions/_site/config.js`의 `url` 값을 고치고 Commit
- 커스텀 도메인: Pages 프로젝트 → **Custom domains → Set up a custom domain**

### 1-6. 정식 공개 전에 꼭 할 일
1. `functions/_site/config.js`의 **`operator`** 칸을 채웁니다: 운영 법인·대표·사업자등록번호·주소·문의 이메일·**개인정보 보호책임자**. 비어 있으면 개인정보처리방침에 "〔운영 개시 전 게시〕"로 표시됩니다.
2. `/privacy/`(개인정보처리방침)와 `/terms/`(이용약관)는 기획서 기준 초안입니다. **법률 전문가 검토**를 받고, 고친 날짜를 `config.js`의 `policyVersion`에 적습니다(가입 동의 기록에 이 값이 남습니다).
3. 네이버 서치어드바이저·구글 서치콘솔 등록 → [docs/SEO-가이드.md](docs/SEO-가이드.md)의 체크리스트대로 진행합니다.

## 2. 글과 문구 고치기

| 고칠 것 | 파일 | 비고 |
|---|---|---|
| 가이드 글 추가·수정 | `functions/_site/guides.js` | 배열 맨 앞에 새 글을 넣습니다. `slug`는 주소이므로 한 번 정하면 바꾸지 않습니다 |
| 홈·소개·운영 방식·규칙·등급·프로그램·FAQ·가입 신청 | `functions/_site/pages.js` | |
| 개인정보처리방침·이용약관 | `functions/_site/legal.js` | |
| 대표 주소·소유확인 코드·운영 주체 | `functions/_site/config.js` | |
| 머리글·바닥글 메뉴 | `functions/_site/layout.js` | |
| 디자인 | `public/assets/site.css` (공개), `public/app/styles.css` (회원) | 포인트 컬러 `--blue: #2457F5` |

GitHub 웹에서 파일 → 연필 아이콘 → 수정 → Commit changes. Build command를 설정해 두었다면 몇 분 뒤 사이트에 반영됩니다.
Build command를 비워 두었다면 컴퓨터에서 `node scripts/build-site.mjs`를 실행하고 바뀐 `public/` 파일까지 함께 올려야 합니다.

새 가이드를 쓰면 공유 이미지도 만들어 두는 게 좋습니다: `node scripts/render-og.mjs` (크롬 필요). 이미지가 없으면 기본 이미지가 쓰입니다.

## 3. 첫 라운드 운영 순서

1. **운영본부 → 규칙 설정**에서 최소 정산 금액, 예산 상한, 포인트, 승급 조건을 확인합니다. (기본값은 통합 기획서 그대로. 바꾸는 것은 운영자만, 이유를 함께 남깁니다)
2. **운영본부 → 라운드**에서 "1기" 같은 라운드를 만들고 모집 마감일을 정한 뒤 상태를 **모집**으로 둡니다. 홈페이지 첫 화면과 가입 신청 페이지에 모집 안내가 자동으로 뜹니다.
3. **운영본부 → 일정·출석**에서 마챌데이·세미나를 등록합니다. 공개 사이트의 `/programs/`에도 다가오는 일정이 자동으로 표시됩니다.
4. 홈페이지의 **가입 신청**(`/apply/`)을 안내합니다. 신청이 오면 **운영본부 → 가입 신청**에서 승인하면 초대 코드와 보낼 이메일 문안이 뜹니다. (가입 주소: `/app/#/register`)
5. 회원은 초대 코드로 가입(약관·개인정보 동의) → 오리엔테이션 → 챌린저(L1). 포인트 300점, 자기 자산 진단, 모임 1회, 가입 14일이 차면 **자동으로 메이커(L2)**가 됩니다.
   - 첫 라운드는 리더가 없으므로 믿을 만한 회원을 **운영본부 → 회원 → 등급·배지·상태 관리**로 리더(L4)로 올리거나, 운영진이 **오피셜 챌린지**를 직접 만듭니다.
6. 리더가 챌린지를 제안하면 **운영본부 → 챌린지 심사**에서 6항목 점수를 매깁니다. 27점 이상이면 승인 → 모집.
7. 그룹장이 그룹원을 수락하고 "모집 마감 → 합의서"를 누르면 합의서를 씁니다. 전원이 서명하면 **운영본부 → 합의서 승인**에 올라오고, 승인하면 **진행 중**으로 바뀌며 4·7·8·12주차 마일스톤이 생깁니다.
8. 매주 그룹장이 체크인을 열고 그룹원이 제출합니다. 완료 기록은 그룹장이 확인해야 포인트·기여율에 반영됩니다.
9. 라운드 말: 그룹장이 **기여율 확정 → 정산표 생성** → 그룹원 전원 확인 → **페이퍼 제출** → 운영본부 **페이퍼 승인** → **정산 검수 승인** → 입금 후 **운영본부 → 지급 관리**에서 지급 처리.
   - 진행 중에는 **운영본부 → 그룹 현황**에서 멈춘 그룹(▲ 주의, ■ 위험)을 매주 확인합니다.
10. 페이퍼를 "외부 공개"로 제출하고 승인하면 `/papers/`와 사이트맵·RSS에 자동으로 올라갑니다.

### 운영본부의 데이터 관리
- **운영본부 → 데이터·백업**: 장부, 정산, 지급, 페이퍼, 포인트 CSV는 운영진 누구나, 회원·가입 신청·동의 기록 CSV와 전체 백업(JSON)은 운영자만 받습니다. 받은 기록은 감사 로그에 남습니다.
- 가입하지 않은 신청서는 처리 후 6개월이 지나면 운영 현황을 열 때 자동으로 파기됩니다(개인정보처리방침 2항).
- 회원 탈퇴는 회원이 **내 정보 → 회원 탈퇴**에서 직접 합니다. 개인정보는 지우고, 함께 만든 합의서·장부·정산 기록은 이름 없이 남깁니다.

## 4. 로컬에서 미리 보기·테스트 (선택)

Node 22.5 이상이 필요합니다. 설치할 패키지는 없습니다.

```bash
npm test                                   # 정산 계산기 6개 케이스 + 전체 흐름 API 테스트(v1.2 포함)
npm run build                              # 공개 페이지 다시 만들기
MACHAL_DB=tests/.tmp/dev.sqlite node tests/api.test.js   # 미리보기용 샘플 데이터
npm run serve                              # http://localhost:8788 (Pages 동작 흉내: 정적 + Functions + 404)
npm run check:seo                          # 모든 공개 페이지의 제목·설명·canonical·OG·JSON-LD·링크 점검
node tests/site-flow.js                    # 가입 신청서 제출·로그인 표시 등 브라우저 동작 점검 (크롬 필요)
node tests/admin-flow.js                   # 운영본부 콘솔 동작 점검: 검색·규칙 변경·단체 알림·메모·권한 (크롬 필요)
node tests/screenshots.js [--mobile]       # 주요 화면 캡처, 운영 화면 22개 포함 (크롬 필요)
```

## 5. 규칙을 바꾸고 싶을 때

- **숫자·비율·조건**: 운영본부 → 규칙 설정(운영자만). 바뀐 값은 즉시 적용되지만 이미 승인된 합의서에는 당시 값이 저장되어 소급되지 않습니다. 공개 사이트의 `/levels/`는 설정값을 불러와 표시합니다.
- **기본값 자체**: `functions/_lib/rules.js` (공개 사이트의 규칙·등급 페이지도 이 값으로 만들어집니다)
- **정산 공식**: `functions/_lib/settlement.js` (순수 함수, `tests/settlement.test.js`로 검증)

## 6. 알아 둘 점

- 비밀번호는 PBKDF2-SHA256(100,000회)으로 저장하고, 세션은 HttpOnly 쿠키입니다. 모든 권한 검사는 서버에서 합니다.
- 같은 이메일로 15분 안에 10번(같은 IP는 30번) 로그인에 실패하면 15분 동안 막습니다.
- 공개 페이지는 `machal_in` 표시 쿠키로만 로그인 여부를 알아내므로, 페이지를 볼 때마다 API를 부르지 않습니다. `_routes.json`으로 Functions는 `/api/*`, `/papers/*`, `/sitemap.xml`, `/rss.xml`에서만 실행됩니다(무료 요청 한도 절약).
- 이메일 자동 발송은 없습니다. 초대 코드·알림은 화면에 표시되고, 운영본부가 이메일/카톡으로 전달합니다.
- 증빙(영수증 등)은 링크로 받습니다. 정산표의 원천징수 3.3%는 **참고용 표시**입니다.
